## 1. 環境構築（setup）

### 1-1. `conda` が見つからない

**症状**

```text
&: The term 'conda' is not recognized as a name of a cmdlet, function, script file, or executable program.
```

**原因**: Miniforge を導入しても、`conda` は自動では PATH に追加されません。

**確認**

```powershell
Test-Path "$env:USERPROFILE\miniforge3\Scripts\conda.exe"
```

**対処**: `setup.ps1` / `setup.sh` は PATH・`CONDA_EXE`・既定インストール先の 3 か所を探すようになっています。
スクリプトを使わず手動で実行する場合は、フル パスで呼び出してください。

```powershell
& "$env:USERPROFILE\miniforge3\Scripts\conda.exe" env create --file environment-local.yml
```

---

### 1-2. ⚠ `conda` コマンドが無言のまま止まる

**症状**: `conda run` や `conda env create` を実行しても、**何も出力されないまま終わらない**。エラーも出ない。

**原因**: **別のターミナルで conda が実行中だと、conda はロックを待って停止します。**
本ハンズオンの構築中は、9 章の `conda env create` が別ターミナルで実行中だったために発生しました。

**確認**（Windows）

```powershell
Get-CimInstance Win32_Process -Filter "Name='conda.exe' OR Name='python.exe'" |
    Select-Object ProcessId, CommandLine | Format-List
```

**対処**: 他の conda 実行が終わるまで待ちます。**プロセスを強制終了すると環境が壊れることがあります。**

---

### 1-3. `verify_env.py` がパッケージ未導入で失敗する

**症状**

```text
NG: 次のパッケージが見つかりません: ipykernel
    セットアップ スクリプト（setup.ps1 / setup.sh）を再実行してください。
```

**原因**: `environment-local.yml` を使わずに手動で `pip install` した場合、
`jupyterlab` や `ipykernel` が入りません。

**対処**: `environment-local.yml` から環境を作り直すか、不足分を追加します。

```powershell
& "$env:USERPROFILE\miniforge3\envs\il-local\python.exe" -m pip install "ipykernel>=6.0"
```

---

### 1-4. VS Code のエディター上だけ `import` がエラーになる

**症状**: `il_common.py` などで `Cannot find implementation or library stub for module named "numpy"` と表示される。
**しかしスクリプトは正常に実行できる。**

**原因**: VS Code が選んでいる Python インタープリターが `il-local` ではありません。

**対処**: コマンド パレットで `Python: Select Interpreter` を実行し、`il-local` を選びます。

## 2. スクリプトの実行

### 2-1. ⚠ 専門家がランダム行動を上回らない

**症状**

```text
ValueError: 専門家がランダム行動を上回っていません (expert=32.10 <= random=32.60)。
 --expert-timesteps を増やしてください（現在 2000）。
```

**原因**: `--expert-timesteps` が小さすぎて、専門家 PPO が学習できていません。

**なぜ止めるのか**: このまま進むと、正規化リターンの分母
`expert_mean - random_mean` が 0 以下になり、**符号が反転した無意味な値**（例: `-129.4`）が出ます。
「専門家から学ぶ」という前提が崩れているため、`collect_demos.py` はここで停止します。

**対処**: `--expert-timesteps` を増やします。
本ハンズオンでは **100,000 steps** で `expert_mean ≈ 498` を確認しています。

---

### 2-2. ⚠ 可変ホライズン環境で GAIL がエラーになる

**症状**

```text
ValueError: Episodes of different length detected: {8, 9, 10, ...}.
Variable horizon environments are discouraged -- termination conditions leak information
about reward. ... If you are SURE you want to run imitation on a variable horizon task,
then please pass in the flag: `allow_variable_horizon=True`.
```

**原因**: `CartPole-v1` のような**エピソード長が変わる環境**で GAIL / AIRL を実行しました。
`imitation` は既定でこれを拒否します。

> **これはバグではなく、意図された安全装置です。** 詳しくは [07 章](07_GAILと評価の落とし穴.md) を参照してください。

**対処**: **固定ホライズンの `seals:seals/CartPole-v0` を使ってください。**
`allow_variable_horizon=True` で回避してはいけません（評価が意味を失います）。

> ⚠ **エラーメッセージ中の URL は `getting-started/variable-horizon.html` ですが、実在するページは
> https://imitation.readthedocs.io/en/latest/main-concepts/variable_horizon.html です。**
> ライブラリ側のメッセージが古い URL を指しています。

---

### 2-3. GAIL が「更新できない」とアサートする

**症状**

```text
AssertionError: No updates (need at least 16384 timesteps, have only total_timesteps=2048)!
```

**原因**: GAIL に渡した学習ステップ数が、生成器（PPO）の 1 ラウンド分に満たない。
1 ラウンドは `n_steps × n_envs`（既定では 2048 × 8 = 16384）です。

**対処**: `--gail-timesteps` を 16,384 以上にします。

---

### 2-4. BC 実行時の `UserWarning`

**症状**

```text
imitation/algorithms/bc.py:236: UserWarning: Converting a tensor with requires_grad=True
to a scalar may lead to unexpected behavior. Consider using tensor.detach() first.
```

**原因**: `imitation` 1.0.1 がログ記録時にテンソルをスカラーへ変換しているためです。
**ライブラリ内部の警告であり、学習結果には影響しません。**

**対処**: 不要です。無視してかまいません。

---

### 2-5. ⚠ ローカル実行すると `mlflow.db` と `mlruns/` が作られる

**症状**: スクリプトを実行したフォルダーに `mlflow.db` と `mlruns/` が生成される。

**原因**: MLflow 3.15.1 は、追跡 URI を設定していないと**カレント ディレクトリ**を記録先にします。

```text
mlflow tracking uri : sqlite:///C:/GitHub/.../mlflow.db
```

**対処**

- Azure ML のジョブとして実行する場合は、追跡先が自動設定されるため発生しません。
- ローカルで試す場合は、**追跡 URI をワークスペースに向ける**か（[03 章](03_AzureML環境構築.md)）、
  生成物を `.gitignore` に追加してください。

```gitignore
mlruns/
mlflow.db
__pycache__/
```
