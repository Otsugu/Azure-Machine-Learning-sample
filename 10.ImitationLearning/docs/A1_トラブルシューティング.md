## 1. 環境構築（setup）

### 1-1.【実際に遭遇】`conda` が見つからない

**症状**

```text
conda: The term 'conda' is not recognized as a name of a cmdlet, function, script file, or executable program.
```

**原因**: Miniforge を導入しても、`conda` は自動では PATH に追加されません。

**確認**

```powershell
Test-Path "$env:USERPROFILE\miniforge3\Scripts\conda.exe"
```

**対処**: `setup.ps1` / `setup.sh` は PATH・`CONDA_EXE`・既定インストール先の 3 か所を探すようになっています。
スクリプトを使わず手動で実行する場合は、フル パスで呼び出してください。

```powershell
& "$env:USERPROFILE\miniforge3\Scripts\conda.exe" env create --file environment-local.yml
```

---

### 1-2.【実際に遭遇】`conda run` を同時に実行すると conda 自身が異常終了する

**症状**: 別の `conda run` が動いている状態でもう 1 つ `conda run` を実行すると、
conda が内部エラー レポートを出して失敗します。

```text
An unexpected error has occurred. Conda has prepared the above report.
If you suspect this error is being caused by a malfunctioning plugin,
consider using the --no-plugins option to turn off plugins.
```

**原因**: conda は同時実行に対してロックを取るため、並行実行に耐えられないことがあります。

**対処**: **`conda run` を経由せず、環境の Python を直接呼びます。**

```powershell
& "$env:USERPROFILE\miniforge3\envs\il-panda\python.exe" your_script.py
```

> **本ハンズオンの構築中は、この方法に切り替えて解決しました。**

---

### 1-3.【設計で回避】`Microsoft Visual C++ 14.0 or greater is required.`

**いつ起きるか**: `pybullet` を **PyPI から** `pip install` しようとしたとき。

PyPI の `pybullet` は **Windows / macOS 向けのビルド済みホイールを公開していません**。
そのため `pip` がソースからのビルドを試み、C++ コンパイラーが無い環境で失敗します。

> 出典（参考情報・サードパーティ）: https://pypi.org/project/pybullet/#files

**本ハンズオンでの回避**: [setup/environment-local.yml](../setup/environment-local.yml) は
**`pybullet` を conda-forge から**導入します（[02 章 2.3](02_環境を準備する.md)）。

> 出典（参考情報・サードパーティ）: https://anaconda.org/conda-forge/pybullet

**もし遭遇したら**: `environment-local.yml` を使わずに `pip install panda-gym` していないか確認してください。

---

### 1-4.【設計で回避】`verify_env.py` がパッケージ未導入で失敗する

**症状**

```text
NG: 次のパッケージが見つかりません: pybullet
    セットアップ スクリプト（setup.ps1 / setup.sh）を再実行してください。
```

**原因**: `environment-local.yml` を使わずに手動で `pip install` した場合、
conda 側のパッケージ（`pybullet` / `numpy` / `scipy`）が入りません。

**対処**: `environment-local.yml` から環境を作り直してください。

## 2. 環境（ピックアンドプレース）の扱い

### 2-1.【実際に遭遇】DAgger が `AssertionError` で止まる

**症状**

```text
  File ".../imitation/policies/base.py", line 41, in _predict
    assert self.observation_space.contains(np_ob_unwrapped)
AssertionError
```

**いつ起きるか**: `SimpleDAggerTrainer` に `NonTrainablePolicy` 派生の専門家を渡して学習させたとき。

**原因**: **panda-gym は観測空間を `Box(-10.0, 10.0, ...)` と宣言していますが、値をクリップしていません。**
学習途中の方策がロボットを激しく動かすと、速度などが ±10 を超えて
`observation_space.contains()` が `False` になります。

> 観測空間の宣言はソースで確認できます。
> 出典（参考情報・OSS 公式ソース）: https://github.com/qgallouedec/panda-gym/blob/master/panda_gym/envs/core.py

**対処**: [src/pick_place_env.py](../src/pick_place_env.py) の **`ClipObservationWrapper`** が
観測を宣言範囲に収めます。**本ハンズオンでは適用済みです。**

> ⚠ **BC の評価だけを見ていると気づけません。** DAgger のように
> **学習途中の方策で環境を動かす手法**で初めて表面化します。

---

### 2-2.【実際に遭遇】可変ホライズン環境で GAIL が `ValueError` になる

**症状**

```text
ValueError: Episodes of different length detected: {1, 50, 11, 34}. Variable horizon
environments are discouraged -- termination conditions leak information about reward. See
https://imitation.readthedocs.io/en/latest/getting-started/variable-horizon.html for more
information. If you are SURE you want to run imitation on a variable horizon task, then
please pass in the flag: `allow_variable_horizon=True`.
```

**原因**: 素の `PandaPickAndPlace-v3` は**成功した瞬間にエピソードが終わります**。
`imitation` は既定でこれを拒否します。

> **これはバグではなく、意図された安全装置です。** 詳しくは [07 章](07_GAILと評価の落とし穴.md) を参照してください。

**対処**: **固定ホライズン化した `il/PandaPickAndPlace-v0` を使ってください。**
`allow_variable_horizon=True` で回避してはいけません（評価が意味を失います）。

---

### 2-3.【実際に遭遇】エラー メッセージ中の URL が実在しない

上記 2-2 のメッセージは次の URL を案内しますが、**このページは存在しません。**

```text
https://imitation.readthedocs.io/en/latest/getting-started/variable-horizon.html
```

**実際に存在するのは次です。**

**https://imitation.readthedocs.io/en/latest/main-concepts/variable_horizon.html**

`imitation` 1.0.1 のメッセージが古い URL を指したままになっています。

### 2-4.【実際に遭遇】成功したのに `info["is_success"]` が消える

**症状**: 固定ホライズン化した環境で、成功した次のステップから `info` が空の辞書になる。

**原因**: `AbsorbAfterDoneWrapper` は吸収状態で `info` を空にします。

> "In this artificial absorb state, we stop calling `self.env.step(action)` ... **`info` is always an empty dictionary.**"
>
> 出典（参考情報・OSS 公式ソース）: https://github.com/HumanCompatibleAI/seals/blob/master/src/seals/util.py

**実測**: 専門家で 1 エピソード動かしたところ、
**`is_success=True` を報告したのは 11 ステップ目の 1 回だけ**で、
**12 ステップ目以降 38 ステップにわたって `info` が空**でした。

**対処**: [src/pick_place_env.py](../src/pick_place_env.py) の **`SuccessRecorderWrapper`** が
エピソード中の成功を保持します。**本ハンズオンでは適用済みです。**
この動作は [notebooks/02_explore_env.ipynb](../notebooks/02_explore_env.ipynb) の 4. で確認できます。

## 3. 学習スクリプトの実行

### 3-1.【実際に遭遇】BC 実行時の `UserWarning`

**症状**

```text
.../imitation/algorithms/bc.py:236: UserWarning: Converting a tensor with requires_grad=True
to a scalar may lead to unexpected behavior. Consider using tensor.detach() first.
```

**原因**: `imitation` 1.0.1 がログ記録時にテンソルをスカラーへ変換しているためです。
**ライブラリ内部の警告であり、学習結果には影響しません。**

**対処**: 不要です。無視してかまいません。

---

### 3-2.【実際に遭遇】⚠ 同じ `--seed` なのに結果が再現しない

**症状**: まったく同じ引数で学習させたのに、成功率が実行のたびに変わる。

**実測例**: DAgger を同じ設定・同じ seed で実行したところ、
ある実行では **成功率 0.00**、別の実行では **成功率 0.15** になりました。

**原因**: **`imitation` の `rng` 引数は、データのシャッフルなどを制御するだけです。**
**ニューラルネットワークの初期値は PyTorch のグローバル乱数が決めます。**
そのため、同じプロセス内で先に別の学習を走らせていると、初期値が変わって結果も変わります。

**対処**: [src/il_common.py](../src/il_common.py) の **`set_seed()`** が
`random` / `numpy` / `torch` の 3 つをまとめて固定します。
[src/train_il.py](../src/train_il.py) と [src/collect_demos.py](../src/collect_demos.py) は
**起動直後にこれを呼びます。** 本ハンズオンでは対応済みです。

> [!IMPORTANT]
> **これは模倣学習に限らない、実験の再現性の基本です。**
> 「シードを渡したから再現する」と思い込まず、**実際に 2 回実行して一致するかを確かめてください。**

---

### 3-3.【設計で回避】専門家がランダム行動を上回らない

[src/collect_demos.py](../src/collect_demos.py) には次の安全装置が入っています。

```python
if expert_mean <= random_mean:
    raise ValueError(
        f"専門家がランダム行動を上回っていません "
        f"(expert={expert_mean:.2f} <= random={random_mean:.2f})。"
        f" scripted_expert.py の制御パラメーターを確認してください。"
    )
```

**なぜ止めるのか**: 正規化リターンの分母 `expert_mean - random_mean` が 0 以下になり、
**符号が反転した無意味な値**が出るためです（[04 章 4.5](04_専門家デモを作る.md)）。

**もし遭遇したら**: [src/scripted_expert.py](../src/scripted_expert.py) の制御パラメーターを確認してください。
本ハンズオンの構築中には、**判定の順序を誤ってスクリプト専門家の成功率が 0.40 まで落ちた**ことがあります
（[04 章 4.2](04_専門家デモを作る.md)）。

---

### 3-4.【実際に遭遇】ローカル実行すると `mlflow.db` が作られる

**症状**: スクリプトを実行したフォルダーに `mlflow.db` が生成される。

**実測**

```text
tracking_uri= sqlite:///C:/.../mlflow.db
```

**原因**: MLflow 3.15.1 は、追跡 URI を設定していないと**カレント ディレクトリ**を記録先にします。

**対処**

- Azure ML のジョブとして実行する場合は、追跡先が自動設定されるため発生しません。
- ローカルで試す場合は、**追跡 URI をワークスペースに向ける**か（[03 章](03_AzureML環境構築.md)）、
  生成物を `.gitignore` に追加してください（本ハンズオンでは設定済みです）。
