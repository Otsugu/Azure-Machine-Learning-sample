## 4.2 まず `PandaReach-v3` を触る（Step A）

### なぜ Reach から始めるのか

[00 章](00_はじめに.md) の 0.3 で説明したとおり、**Reach は「手先を目標位置に動かすだけ」**なので、
ランダムに動かしても**たまたま成功します**。つまり**学習が確実に進む**ので、
「環境・ジョブ・記録の仕組みが正しいか」を検証する土台として最適です。

### 見るべきもの

```python
import gymnasium as gym
import panda_gym   # ← これを import しないと環境 ID が登録されない

env = gym.make("PandaReach-v3", render_mode="rgb_array", renderer="Tiny")

print(env.observation_space)   # 辞書型（Dict）
print(env.action_space)        # 連続値（Box）
print(env.spec.max_episode_steps)
```

| 確認項目 | 何を意味するか |
|---|---|
| `observation_space` が **`Dict`** | **Goal-conditioned RL の環境である**（[01 章](01_強化学習の基礎.md) 1.5） |
| `action_space` が **`Box`** | 連続値制御 → **SAC / TD3 が使える**（DQN は使えない） |
| `action_space.shape` が **`(3,)`** | Reach は**グリッパーを使わない**（`block_gripper=True`）ので 3 次元（dx, dy, dz） |
| `max_episode_steps` が **`50`** | 1 エピソードは最大 50 ステップ |

> ⚠ **`import panda_gym` を忘れると `gym.error.NameNotFound` になります。**
> これは「使っていない import」に見えるため削除されがちですが、**環境 ID の登録に必須**です。

> ⚠ **`render_mode` の使い分け（4.6 で詳しく扱います）**
>
> | 実行場所 | 指定 |
> |---|---|
> | 手元の PC（GUI を見たい） | `render_mode="human"` |
> | 手元の PC / **Azure ML Compute**（動画を残したい） | `render_mode="rgb_array"` ＋ `renderer="Tiny"` |
>
> **Azure ML のコンピューティングはヘッドレスなので、`"human"` は使えません。**
> 本章の以降のコードは、どちらでも動く **`"rgb_array"` ＋ `"Tiny"`** を使います。

## 4.3 `PandaPickAndPlace-v3` の観測を読む（Step B の準備）

### 辞書型観測の3つのキー

```python
obs, info = env.reset(seed=0)
for key, value in obs.items():
    print(f"{key:15s} shape={value.shape}")
```

| キー | 意味 | `PandaReach-v3` | `PandaPickAndPlace-v3` |
|---|---|---|---|
| `observation` | ロボット（と対象物）の状態 | 手先の位置・速度 | 手先の位置・速度・グリッパー開度 ＋ **キューブの位置・姿勢・速度・角速度** |
| `achieved_goal` | **実際に達成した位置** | **手先の位置** | **キューブの位置** |
| `desired_goal` | **達成したい位置**（目標） | 目標点 | 目標点 |

> **重要**: **目標位置は `observation` ではなく `desired_goal` に入っています。**
> ここを取り違えると「方策が目標を見ていない」というバグになります。

> **重要（Reach と PickAndPlace の決定的な違い）**
> `achieved_goal` が **`Reach` では手先**、**`PickAndPlace` ではキューブ**です。
> - Reach: エージェントは `achieved_goal` を**直接**動かせる → 簡単
> - PickAndPlace: エージェントは `achieved_goal` を**間接的にしか**動かせない（つかむ必要がある） → 難しい
>
> **これが「Reach は学習できて PickAndPlace は学習できない」の本質です。**

## 4.4 【体感】疎な報酬の難しさを測る

### やること

**ランダム方策で 100 エピソード動かし、成功率を測ります。**

```python
successes = 0
for ep in range(100):
    obs, info = env.reset(seed=1000 + ep)
    done = False
    while not done:
        obs, reward, terminated, truncated, info = env.step(env.action_space.sample())
        done = terminated or truncated
    successes += int(info["is_success"])
print("成功率:", successes / 100)
```

### 期待される結果（**この差を必ず体感してください**）

| 環境 | ランダム方策の成功率 |
|---|---|
| `PandaReach-v3` | **0 ではない値になります**（手先を直接動かせるため、たまたま目標に入る） |
| `PandaPickAndPlace-v3` | **ほぼ 0 になります** |

> ⚠ **具体的な数値は乱数とバージョンに依存するため、本テキストでは断定しません。**
> **実際に測った値をワークシートに記録してください。**

> **重要**: PickAndPlace で成功率が 0 ということは、
> **「エージェントは学習を始めるための『成功した経験』を1つも持っていない」**ことを意味します。
> これが [01 章](01_強化学習の基礎.md) 1.4 で説明した**疎な報酬の壁**です。
> **HER はこの壁を越えるための手法です。**

## 4.5 「成功」がどこで決まっているかを確認する

> **検証済みの重要な事実**（`panda_gym/envs/tasks/pick_and_place.py` で確認）
>
> 1. `is_success` は **キューブと目標の距離が `distance_threshold`（既定 **0.05 m**）未満か**だけを見ています。
>    **「つかんでいるか」は一切判定しません。**
> 2. 目標位置は、**約 30% の確率でテーブル上、約 70% の確率で空中**にサンプルされます
>    （`if self.np_random.random() < 0.3: noise[2] = 0.0`）。
>
> 出典（参考情報・OSS 公式ソース）:
> https://github.com/qgallouedec/panda-gym/blob/master/panda_gym/envs/tasks/pick_and_place.py

### これが意味すること（**改善実験の議論の核心**）

> ⚠ **キューブを「つかまずに押して転がす」だけでも、目標がテーブル上（約 30%）なら環境は「成功」と判定します。**
>
> つまり **「持ち上げを一切学習していなくても、成功率は理論上 30% まで上がりうる」**ということです。

> **重要（論理の飛躍を避ける）**
> 逆は必ずしも成り立ちません。**「成功率 30% ＝ 必ず押しているだけ」とは限りません。**
> 次のどれもあり得ます。
>
> | 可能性 | 判別方法 |
> |---|---|
> | (a) 押しているだけ（報酬ハッキング） | **動画でグリッパーが閉じているかを見る** |
> | (b) 空中の目標にも時々成功しているが不安定 | 動画で持ち上げを確認。`final_std_reward` が大きい |
> | (c) 単に学習が途中 | 学習曲線がまだ上昇傾向にある |
>
> **数値だけで断定せず、必ず評価動画を見て判定してください。**（判定の手順は [06 章](06_結果の読み解き.md) の 6.3）
>
> これはバグではなく、**成功判定の設計が生む典型的な報酬ハッキングの土壌**です。
> 実務では **「報酬関数」だけでなく「成功判定そのもの」を見直す必要がある**ことを示しています（例: 「持ち上げた高さ」を成功条件に加える）。

### 演習

`env.reset()` を 300 回繰り返し、`desired_goal` の z 座標の分布を見てください。
**z がキューブ半分の高さ（約 0.02）に集中するグループと、それより上に連続的に広がるグループの 2 種類**に分かれるはずです。
（実装は [notebooks/02_explore_rl_env.ipynb](../notebooks/02_explore_rl_env.ipynb) の 4 節にあります）

## 4.6 ロボットの動きを「見る」— ローカルは GUI、クラウドは動画

**ロボットが動く様子を見ることは、強化学習では必須の作業**です。
[01 章](01_強化学習の基礎.md) 1.7 のとおり、**報酬ハッキングを検出する最も確実な手段が「見ること」**だからです。

ただし **見る方法は実行場所によって変わります。**

| 実行場所 | 使える方法 | 指定 |
|---|---|---|
| **手元の PC / Mac** | **① GUI シミュレーター（リアルタイム表示）**<br>② 動画ファイル | `render_mode="human"`<br>`render_mode="rgb_array"` |
| **Azure ML Compute（クラウド）** | **② 動画ファイルのみ** | `render_mode="rgb_array"` ＋ `renderer="Tiny"` |

> ⚠ **クラウドでは GUI は使えません。**
> Azure ML のコンピューティングは**ヘッドレス**（画面を持たない）ため、OpenGL のウィンドウを開けません。
> **「ロボットが動く様子をリアルタイムで見る」体験は、ローカル実行でしか得られません。**

---

### 4.6.1 ① ローカルで GUI を開く（**この章で一度は体験してください**）

```python
import gymnasium as gym
import panda_gym

# human モードは PyBullet の 3D GUI ウィンドウを開く（ローカル実行専用）
env = gym.make("PandaPickAndPlace-v3", render_mode="human")

obs, info = env.reset(seed=0)
for _ in range(200):
    obs, r, terminated, truncated, info = env.step(env.action_space.sample())
    if terminated or truncated:
        obs, info = env.reset()
env.close()
```

**何が起きるか**（panda-gym のソースで確認済み）

```python
# panda_gym/pybullet.py の PyBullet.__init__
if self.render_mode == "human":
    self.connection_mode = p.GUI          # ← OpenGL ウィンドウを開く
elif self.render_mode == "rgb_array":
    if renderer == "OpenGL":
        self.connection_mode = p.GUI
    elif renderer == "Tiny":
        self.connection_mode = p.DIRECT   # ← ウィンドウを開かない（ヘッドレス）
```

> **出典（参考情報・OSS 公式ソース）**: https://raw.githubusercontent.com/qgallouedec/panda-gym/master/panda_gym/pybullet.py

#### ⚠ panda-gym の GUI で「できないこと」（**知らないと必ず戸惑います**）

panda-gym は GUI 接続の直後に、次の 2 行を実行します。

```python
self.physics_client.configureDebugVisualizer(p.COV_ENABLE_GUI, 0)
self.physics_client.configureDebugVisualizer(p.COV_ENABLE_MOUSE_PICKING, 0)
```

| できること | できないこと |
|---|---|
| 3D シーンの表示 | **PyBullet のデバッグ パネル（スライダー・ボタン類）の表示** |
| カメラ操作（`place_visualizer()` → `resetDebugVisualizerCamera()`） | **マウスでオブジェクトをドラッグして掴む操作** |

> **重要**: **「Web 記事で見た PyBullet のスライダーが出ない」のは不具合ではなく、panda-gym の仕様です。**
> panda-gym が意図的に無効化しています。

#### ⚠ `human` モードでは動画を作れません

`render()` は **`rgb_array` のときだけ画像を返し、それ以外は `None` を返します**（docstring に明記）。

> 「If render mode is 'rgb_array', return an RGB array of the scene. **Else, do nothing and return None.**」
> → 出典（参考情報・OSS 公式ソース）: 上記 `panda_gym/pybullet.py`

つまり **`human` と `rgb_array` は同時には使えません。**
**動画を残したいなら `rgb_array` を選んでください。**

> **補足（ドキュメントと実装の不一致）**
> docstring は「Only "OpenGL" is available for human render mode」と書いていますが、
> **実コードでは `human` のとき `renderer` 引数は参照されず、無条件に `p.GUI` になります。**
> **本テキストは実コードの挙動に従います。**

### 4.6.2 ② 動画ファイルを保存する（**クラウドではこちらだけ**）

```python
import imageio.v2 as imageio

# "Tiny" は PyBullet のソフトウェア レンダラー（p.DIRECT）。GPU も X サーバーも不要
env = gym.make("PandaPickAndPlace-v3", render_mode="rgb_array", renderer="Tiny")

frames = []
obs, info = env.reset(seed=0)
done = False
while not done:
    frames.append(env.render())          # rgb_array が返る
    obs, r, terminated, truncated, info = env.step(env.action_space.sample())
    done = terminated or truncated
env.close()

with imageio.get_writer("random_policy.mp4", fps=20) as w:
    for f in frames:
        w.append_data(f)
```

> **重要**: `env.render()` が `None` を返す場合、**`render_mode` を指定せずに環境を作っています。**
> `gym.make(..., render_mode="rgb_array")` を確認してください。

#### なぜクラウドでは `Tiny`（＝`p.DIRECT`）なのか

**PyBullet の公式ガイドが、この構成を明確に推奨しています。**

> "The DIRECT connection sends the commands directly to the physics engine, without using any transport layer and **no graphics visualization window**"
>
> "Note that in **DIRECT mode you cannot access the OpenGL and VR hardware features** ... DIRECT mode does allow rendering of images using the built-in software renderer through the 'getCameraImage' API. **This can be useful for running simulations in the cloud on servers without GPU.**"
>
> → 出典（参考情報・OSS 公式ドキュメント）: [PyBullet Quickstart Guide](https://raw.githubusercontent.com/bulletphysics/bullet3/master/docs/pybullet_quickstart_guide/PyBulletQuickstartGuide.md.html)

> **これが本テキストの設計根拠です。**
> **Azure ML Compute で動かす学習ジョブは、常に `render_mode="rgb_array"` ＋ `renderer="Tiny"` を使います**（[05 章](05_ベースライン実験.md) 5.2 参照）。

### 4.6.3 カメラの位置を変える

> **深く理解するために**
>
> 本節は必須ではありません。**「見たい角度から見る」ための追加情報**です。

#### カメラの初期位置は `gym.make` の引数で決まる

| `render_yaw` | `45` | GUI ／ `rgb_array` の両方 |
| `render_pitch` | `-30` | GUI ／ `rgb_array` の両方 |
| `render_roll` | `0` | **`rgb_array` だけ**（下の警告を参照） |
| `render_width` / `render_height` | `720` / `480` | **`rgb_array` だけ**（画像サイズ） |

> **出典（参考情報・OSS 公式ソース）**: [panda_gym/envs/panda_tasks.py](https://github.com/qgallouedec/panda-gym/blob/master/panda_gym/envs/panda_tasks.py) ／ [panda_gym/envs/core.py](https://github.com/qgallouedec/panda-gym/blob/master/panda_gym/envs/core.py)

### 4.6.4 ロボットを手で動かして「行動」の意味を掴む

> [!TIP]
> **深く理解するために**
>
> 本節は必須ではありません。ただし **`--total-timesteps` や報酬設計を議論する前に、一度は自分でロボットを動かしておくこと**を強く勧めます。
> **「人間が操作しても掴んで持ち上げるのは難しい」**という体感が、[06 章](06_結果の読み解き.md) 6.0 の「学習しないのは失敗ではない」を腹落ちさせます。

#### まず行動ベクトルの中身を知る

`PandaPickAndPlace-v3` の行動空間は **`Box(-1.0, 1.0, shape=(4,))`** です（`control_type="ee"` かつ `block_gripper=False` のため）。中身は次のとおりです（**ソースで確認済み**）。

| 要素 | 意味 | 内部での扱い |
|---|---|---|
| `action[0:3]` | **手先の移動量**（dx, dy, dz） | **`× 0.05`** されてから現在位置に加算 → **1 ステップの移動は最大 5 cm** |
| `action[3]` | **指の開閉量** | **`× 0.2`** されて現在の指幅に加算。**正の値で開き、負の値で閉じる** |

さらに、目標手先位置の z は **`max(0, z)` でクリップ**されます（テーブル面より下に潜らない）。
`control_type="joints"` を指定すると、行動は **7 関節 ＋ 指の 8 次元**に変わります。

> **出典（参考情報・OSS 公式ソース）**: [panda_gym/envs/robots/panda.py](https://github.com/qgallouedec/panda-gym/blob/master/panda_gym/envs/robots/panda.py)

#### 観測ベクトルの並び（`observation` キー）

`observation` は「ロボットの観測 ＋ タスクの観測」を連結したものです（**ソースで確認済み**）。

| インデックス | 中身 |
|---|---|
| `observation[0:3]` | 手先の位置 |
| `observation[3:6]` | 手先の速度 |
| `observation[6]` | **指の開き幅** |
| `observation[7:19]` | キューブの位置・回転・速度・角速度（各 3 次元） |

> **出典（参考情報・OSS 公式ソース）**: [panda_gym/envs/core.py](https://github.com/qgallouedec/panda-gym/blob/master/panda_gym/envs/core.py) ／ [panda_gym/envs/robots/panda.py](https://github.com/qgallouedec/panda-gym/blob/master/panda_gym/envs/robots/panda.py) ／ [panda_gym/envs/tasks/pick_and_place.py](https://github.com/qgallouedec/panda-gym/blob/master/panda_gym/envs/tasks/pick_and_place.py)

#### 手で操作してみる（**ローカル実行専用**）

```python
import gymnasium as gym
import numpy as np
import panda_gym

env = gym.make("PandaPickAndPlace-v3", render_mode="human", render_distance=0.8, render_pitch=-15)
obs, info = env.reset(seed=0)

MOVES = {
    "w": [ 1.0,  0.0,  0.0,  0.0],   # 手先を +x へ
    "s": [-1.0,  0.0,  0.0,  0.0],   # 手先を -x へ
    "a": [ 0.0,  1.0,  0.0,  0.0],   # 手先を +y へ
    "d": [ 0.0, -1.0,  0.0,  0.0],   # 手先を -y へ
    "r": [ 0.0,  0.0,  1.0,  0.0],   # 手先を上へ
    "f": [ 0.0,  0.0, -1.0,  0.0],   # 手先を下へ
    "o": [ 0.0,  0.0,  0.0,  1.0],   # 指を開く
    "c": [ 0.0,  0.0,  0.0, -1.0],   # 指を閉じる
}

steps = 0
while True:
    key = input("w/s/a/d/r/f/o/c（q で終了）> ").strip()
    if key == "q":
        break
    if key not in MOVES:
        continue
    obs, reward, terminated, truncated, info = env.step(np.array(MOVES[key], dtype=np.float32))
    steps += 1
    print(f"[{steps:>3}] 手先={np.round(obs['observation'][:3], 3)} "
          f"指幅={obs['observation'][6]:.3f} "
          f"キューブ={np.round(obs['achieved_goal'], 3)} "
          f"目標={np.round(obs['desired_goal'], 3)} "
          f"報酬={reward:.1f} 成功={info['is_success']}")
    if terminated or truncated:
        print("--- エピソード終了。リセットします ---")
        obs, info = env.reset()
        steps = 0
env.close()
```

> [!NOTE]
> このセルは `input()` でキー入力を待つため、**ターミナルまたはローカルの Jupyter で実行**してください。
> **Azure ML Compute では GUI が開けないため実行できません**（4.6）。

#### ここで確認してほしいこと

| 確認項目 | なぜ重要か |
|---|---|
| **1 ステップの移動量が小さい**（最大 5 cm） | **`max_episode_steps` が 50** であることの厳しさが体感できる。到達だけで多くのステップを使う |
| **掴んで持ち上げるのが難しい** | 疎な報酬でランダム探索が成功を引けない理由（[00 章](00_はじめに.md) 0.3）が腹落ちする |
| **キューブを押すだけで `成功=True` になる場面を再現できる** | 目標がテーブル上（約 30%）のとき。**4.5 の「報酬ハッキングの土壌」を自分の手で再現できる** |
| **`報酬` は成功するまでずっと `-1.0`** | 疎な報酬（sparse）の定義そのもの。学習信号がいかに乏しいかが分かる |

### 4.6.5 まとめ — 使い分けの指針

| やりたいこと | 実行場所 | 設定 |
|---|---|---|
| ロボットの動きを**リアルタイムで観察**したい | ローカル | `render_mode="human"` |
| **カメラ アングルを変えたい** | ローカル / クラウド両方 | `render_distance` / `render_yaw` / `render_pitch`（4.6.3） |
| **行動の意味を手で確かめたい** | ローカル | `render_mode="human"` ＋ 手動操作（4.6.4） |
| **報酬ハッキングを検出**したい（動画を残す） | ローカル / クラウド両方 | `render_mode="rgb_array"` ＋ `renderer="Tiny"` |
| **学習済みモデルの動きを見たい** | ローカル | `render_mode="human"` ＋ `SAC.load`（[06 章](06_結果の読み解き.md) 6.3.1） |
| **学習ジョブを回す**（描画不要で最速） | クラウド | 本テキストの [src/rl_env_factory.py](../src/rl_env_factory.py) は `render=False` のとき `render_mode` を渡しません |

> **重要**: **学習ジョブでは毎ステップの描画は行いません。** 描画は評価フェーズだけで行います。
> 物理シミュレーションより描画のほうが重いため、**学習中に描画すると大幅に遅くなります。**
