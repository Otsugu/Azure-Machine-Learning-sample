## 9.3 モデルを登録する（任意）

有望な方策があれば、**Azure ML のモデル レジストリ**に登録してバージョン管理できます。

```python
from azure.ai.ml.entities import Model
from azure.ai.ml.constants import AssetTypes

#  job_name は Azure ML が生成したジョブ名（= ジョブ ID）。
#  例: returned_job.name で取得できるもの。表示名（display_name）ではないので注意。
job_name = returned_job.name

model = Model(
    path=f"azureml://jobs/{job_name}/outputs/artifacts/model.zip",
    name="rl-pnp-sac-her",
    type=AssetTypes.CUSTOM_MODEL,
    description="PandaPickAndPlace SAC+HER baseline",
)
ml_client.models.create_or_update(model)
```

> ⚠ **パスが解決できない場合**は、studio のジョブ詳細 → **［出力とログ］** で実際の成果物パスを確認してください。

> **出典: Microsoft Learn** — [How Azure Machine Learning works: resources and assets](https://learn.microsoft.com/azure/machine-learning/concept-azure-machine-learning-v2?view=azureml-api-2)

> ⚠ **HER で学習したモデルを読み込むときは、必ず環境を一緒に渡してください。**

> model = SAC.load("model.zip", env=env)
> ```

## 9.4 Azure のコストを確認する

### 確認方法

| 方法 | 手順 |
|---|---|
| **Microsoft Cost Management** | Azure Portal → 検索バーで「コスト管理」→［コスト分析］→ **タグ `project = rl-workshop` でフィルター** |
| リソース グループ単位 | Portal → 該当リソース グループ →［コスト分析］ |
| 単価の確認 | [Azure Machine Learning 価格](https://azure.microsoft.com/pricing/details/machine-learning/) |
| 見積もり | [Azure 料金計算ツール](https://azure.microsoft.com/pricing/calculator/) |

> **本テキストは具体的な金額を記載しません。**
> 価格はリージョン・VM サイズ・時期により変わるため、**必ず上記で実際の値を確認してください。**

### 記録する項目（「Azure 利用状況・コスト確認表」）

| 項目 | 値 |
|---|---|
| 実行したジョブ数 | |
| 合計学習時間（`train_minutes` の総和） | |
| 使用した VM サイズ | |
| 最大同時実行ノード数 | |
| コンピューティング インスタンスの稼働時間 | |
| **タグ別のコスト（`project=rl-workshop`）** | |

### コストを下げる打ち手（継続検証向け）

| 打ち手 | 効果 | 注意 |
|---|---|---|
| **`min_instances=0`** | ジョブが無い間のコンピューティング課金が止まる | **既に適用済み** |
| **`idle_time_before_scale_down` を短くする** | ノードの解放が早くなる | 短すぎると起動待ちが増える |
| **コンピューティング インスタンスのアイドル シャットダウン** | 消し忘れを防ぐ | **必須** |
| **ジョブの `limits.timeout`** | 暴走した学習を止める | — |
| **Sweep の早期終了ポリシー** | 見込みのない trial を打ち切る | **RL では `delay_evaluation` 必須**（[08 章](08_演習2_ハイパーパラメータ改善.md) 8.4） |
| **Spot（低優先度）の計算資源** | **大幅に安くなる** | **中断される。チェックポイントとセットで設計する** |

#### Spot を使う場合（継続検証向け・ハンズオン中は非推奨）

サーバーレス コンピューティングでは `queue_settings.job_tier` を `Spot` にします。

```python
job = command(
    code="./src",
    command="python train_rl.py",
    environment="rl-panda-gym-env@latest",
    # compute を指定しない → サーバーレス コンピューティング
    resources={"instance_type": "Standard_DS3_v2", "instance_count": 1},
    queue_settings={"job_tier": "Spot"},
)
```

> **出典: Microsoft Learn** — [Model training on serverless compute](https://learn.microsoft.com/azure/machine-learning/how-to-use-serverless-compute?view=azureml-api-2#configure-properties-for-command-jobs)
> 「`queue_settings` で専用 VM（`job_tier: Standard`）と低優先度 VM（`job_tier: Spot`）を選べます。既定は `Standard` です」

> ⚠ **重要な補足（提供終了の情報）**
> Azure ML の **Low priority VM は 2026 年 3 月 31 日をもって提供終了しました**（**本テキスト作成時点（2026-08-13）では既に終了済み**）。
> `tier: low_priority` を指定したコンピューティング クラスターは引き続き検証を通り実行もされますが、
> **Azure Batch が Spot VM としてノードを割り当てます**（システム主導の移行）。Spot の価格と退去挙動が適用されます。
> → 出典: [Use low priority VMs for batch deployments](https://learn.microsoft.com/azure/machine-learning/how-to-use-low-priority-batch?view=azureml-api-2)
>
> **これから設計するなら、サーバーレス ＋ `job_tier: Spot` を使ってください。**
> なお、**価格・提供状況は変更される可能性があるため、必ず上記の Microsoft Learn ページで最新情報を確認してください。**

## 9.5 【必須】後片付け

> ⚠⚠ **ここを飛ばさないでください。課金が続きます。**

### 手順（上から順に）

| # | 対象 | 操作 | 課金への影響 |
|---|---|---|---|
| 1 | **コンピューティング インスタンス** | **停止**（または削除） | **停止で課金が止まる。ただしクォータは解放されない** |
| 2 | 実行中のジョブ | すべて完了またはキャンセル | `sleep infinity` のジョブが残っていないか確認 |
| 3 | コンピューティング クラスター | `min_instances=0` を確認（ノード 0 になる） | ノードが 0 なら計算の課金は止まる |
| 4 | **ワークスペース関連リソース**（残す場合） | ストレージ・Container Registry は**残ると課金される** | 少額だが継続する |
| 5 | **すべて不要な場合** | **リソース グループごと削除** | **確実に止まる** |

### 実行中ジョブの確認とキャンセル

```python
# 実行中のジョブを探す
for job in ml_client.jobs.list():
    if job.status in ("Running", "Queued", "Preparing"):
        print(job.name, job.status, job.display_name)

# キャンセル
ml_client.jobs.begin_cancel("<ジョブ名>")
```

### リソース グループごと削除する（最も確実）

```powershell
# ⚠ 元に戻せません。成果物を先にダウンロードしてください
az group delete --name rg-rl-workshop-<yourname> --yes --no-wait
```

> ⚠⚠ **削除する前に、必要な成果物を必ずダウンロードしてください。**
> - `eval_video.mp4`（動画）
> - `run_summary.json` / `pip_freeze.txt`
> - 比較表の CSV（9.1）
> - `model.zip`（必要なら）
>
> **[notebooks/06_compare_and_cleanup.ipynb](../notebooks/06_compare_and_cleanup.ipynb) にダウンロード用のセルがあります。先に実行してください。**

### 残す場合の方針

| 判断 | 残すもの | 消すもの |
|---|---|---|
| 継続検証する | ワークスペース、環境（Environment）、MLflow の記録 | **コンピューティング インスタンス**（停止で可） |
| 記録だけ残す | ワークスペース（記録の保管庫として） | コンピューティング一式 |
| すべて終了 | ローカルにダウンロードした成果物のみ | **リソース グループごと** |

## ⚠ うまくいかないときは（Step 09）

| # | 症状 | 主な原因 | 確認手順 | 対処 |
|---|---|---|---|---|
| 1 | `search_runs` が空を返す | 実験名の綴り違い／トラッキング URI 未設定 | studio ［ジョブ］の実験名 | 実験名を確認。`mlflow.set_tracking_uri(...)` を実行 |

| 3 | 学習曲線が取れない | `search_runs` は最終値のみ | — | `MlflowClient().get_metric_history(run_id, key)` を使う |
| 4 | **コストが想定より高い** | コンピューティング インスタンスの消し忘れ／`sleep infinity` のジョブ | Cost Management、実行中ジョブ一覧 | 9.5 を実施。**`delete-after` タグを付けておくと発見しやすい** |
| 5 | リソース グループを削除できない | ロックがかかっている／リソースが使用中 | Portal ［ロック］ | ロックを解除する。実行中ジョブをキャンセルする |
