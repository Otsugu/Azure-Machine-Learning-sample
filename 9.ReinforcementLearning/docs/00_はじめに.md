## 0.2 なぜ「ピックアンドプレイス」を題材にするのか

製造現場でのロボット活用を検討するとき、**最も基本的で、かつ最も応用が広いタスク**が「対象物をつかんで（Pick）、指定の場所に置く（Place）」です。

このタスクは強化学習の教材としても優れています。

| 特徴 | 学習上の意味 |
|---|---|
| **成功／失敗が明確** | 評価指標（成功率）を定義しやすい |
| **報酬が疎（sparse）になりやすい** | **強化学習の最大の難所を最初から体験できる** |
| **中間目標が自然に定義できる** | 報酬シェーピングの演習に向く |
| **実機との差（Sim-to-Real）が論点になる** | 製造適用の議論に直結する |

本テキストでは **panda-gym** の `PandaPickAndPlace-v3`（Franka Emika Panda ロボットのピックアンドプレイス環境）を使用します。

> **参考情報（サードパーティ）**: panda-gym の環境一覧
> https://panda-gym.readthedocs.io/en/latest/usage/environments.html

## 0.3 3段階で進めます（**初挑戦者にとって最重要の設計**）

**いきなり `PandaPickAndPlace-v3` に挑むと、ほぼ確実に「何も学習しない」結果になります。**
理由は後述しますが（[01_強化学習の基礎.md](01_強化学習の基礎.md) の 1.4）、報酬が**疎**だからです。

そこで本テキストは、**必ず成功体験を挟んでから難所に入る**構成にしています。

| 段階 | 環境 | アルゴリズム | 目的 | 主な章 |
|---|---|---|---|---|
| **Step A** | `PandaReach-v3` | **SAC（HER なし）** | **ジョブが通り、MLflow に記録され、学習曲線が上がることを確実に体験する** | 03, 04 |
| **Step B** | `PandaPickAndPlace-v3` | **SAC + HER**（比較用に HER なしも実行） | ベースライン実験。**疎な報酬の難しさと HER の効果を体験する** | 05, 06 |
| **Step C** | 同上 | SAC + HER + 報酬・ハイパラ変更 | 改善実験 | 07, 08 |

### なぜ Step A （Reach）は HER なしでも学習できるのか

**どちらも「疎な報酬」なのに、Reach は学習できて PickAndPlace はできない** —— この違いは **「偶然成功する確率」** で説明できます。

| | `PandaReach-v3` | `PandaPickAndPlace-v3` |
|---|---|---|
| 達成対象（`achieved_goal`） | **ロボットの手先の位置** | **キューブ（対象物）の位置** |
| 成功のために必要なこと | 手先を目標位置に動かすだけ | **接近 → 把持 → 持ち上げ → 搜送 → 放す** の連携 |
| ランダム行動での成功 | **手先は直接制御できるので、たまたま入ることがある** | **ほぼ起きない** |

> **重要**: 強化学習は「成功した経験」が一定数集まらないと学習が始まりません。
> Reach はランダム探索でも成功を引けるので HER なしでも学習が進みます。
> PickAndPlace は引けないので、**HER で「成功したことにする」仕組みが必要になります**（詳細は [01_強化学習の基礎.md](01_強化学習の基礎.md) の 1.5）。

> **重要**: Step A は「練習」ではありません。**成果物「Azure 実験環境確認票」そのもの**です。ここで環境が動くことを確認できていないと、以降の実験が全部止まります。

## 0.4 なぜ Azure Machine Learning を使うのか

強化学習の実験は、**普通の機械学習より「実験管理」が重要**です。理由は3つあります。

1. **同じ設定でも結果がばらつく**（乱数シードの影響が非常に大きい）
   → 1回の結果で判断できない。**複数回の実行を体系的に記録・比較する仕組みが要る**
2. **学習に時間がかかる**
   → 手元の PC で回すと他の作業ができない。**クラウドに投げて並列で回したい**
3. **報酬関数を頻繁に書き換える**
   → 「どのコードで出た結果か」が分からなくなる。**コードと結果の紐付けが自動でほしい**

Azure Machine Learning はこの3つに、それぞれ次の機能で応えます。

| 課題 | Azure ML の機能 | 出典 |
|---|---|---|
| 結果がばらつく | **Sweep Job**（ハイパーパラメーター**だけでなく乱数シードも探索対象にできる**。複数条件を並列実行し、平行座標プロットで比較） | [ハイパーパラメーター調整](https://learn.microsoft.com/azure/machine-learning/how-to-tune-hyperparameters?view=azureml-api-2) |
| 時間がかかる | **コンピューティング クラスターの自動スケール**（使わない間はノード 0） | [クラスターの作成](https://learn.microsoft.com/azure/machine-learning/how-to-create-attach-compute-cluster?view=azureml-api-2) |
| コードと結果の紐付け | **ジョブ実行時のコード スナップショット自動保存 ＋ MLflow トラッキング** | [リソースとアセット](https://learn.microsoft.com/azure/machine-learning/concept-azure-machine-learning-v2?view=azureml-api-2) ／ [MLflow](https://learn.microsoft.com/azure/machine-learning/concept-mlflow?view=azureml-api-2) |

> **補足**: 「Sweep Job = ハイパーパラメーター探索」と思われがちですが、**探索空間に `seed` を入れれば「同一設定 × 複数シードの反復実行」を 1 本のジョブで回せます。**
> これは強化学習の**再現性評価に直結**する使い方です（実装は [08 章](08_演習2_ハイパーパラメータ改善.md)）。

## 0.5 【重要】Azure ML の「強化学習専用機能」について

インターネットで検索すると、Azure Machine Learning の**強化学習専用機能**（`azureml-contrib-reinforcementlearning`、いわゆる "Ray on AML"）に関する記事が見つかります。

> ⚠ **これは非推奨です。本テキストでは使用しません。**
>
> Microsoft の公式 API リファレンスに、**RL のサービス非推奨を通知するための警告ユーティリティ**（`warn_rl_is_deprecated`）が記載されています。
> → 出典: [azureml.contrib.train.rl.utils - Microsoft Learn](https://learn.microsoft.com/python/api/azureml-contrib-reinforcementlearning/azureml.contrib.train.rl.utils?view=azure-ml-py)

同様に、以下も**本テキストでは扱いません**。

| 対象 | 状態 | 出典 |
|---|---|---|
| Azure ML の **Low priority VM** | **2026年3月31日に提供終了。** `tier: low_priority` を指定したクラスターは引き続き動作するが、Azure Batch が **Spot VM として割り当てる**（システム主導の移行） | [Use low priority VMs for batch deployments](https://learn.microsoft.com/azure/machine-learning/how-to-use-low-priority-batch?view=azureml-api-2) |
| Azure AI **Personalizer**（RL ベースのサービス。Azure ML ではない） | 2023年9月20日以降**新規作成不可**。**2026年8月25日にサービス終了**。移行先として OSS の [microsoft/learning-loop](https://github.com/microsoft/learning-loop)（MIT）を推奨 | [What is Reinforcement Learning?（Personalizer）](https://learn.microsoft.com/azure/ai-services/personalizer/concepts-reinforcement-learning) |
| Azure ML SDK **v1 形式のロギング API** | **v2 には v1 形式のロギング API はありません。** 代わりに **MLflow で記録します**（これが公式推奨の方法です） | [Log metrics, parameters, and files with MLflow](https://learn.microsoft.com/azure/machine-learning/how-to-log-view-metrics?view=azureml-api-2) |

> **誤解しないでください**: 「v2 では記録できない」のではありません。**v2 では MLflow が標準の記録手段**であり、本テキストもこれを使います。

### では Azure ML に強化学習のうまみは無いのか？

**そんなことはありません。** 専用機能ではなく、**汎用機能の中に「RL の実験だからこそ効く」ものが多数あります。**

本テキストでは、以下を実際に使います。

| 機能 | 何が嬉しいか | 本テキストの該当章 |
|---|---|---|
| **対話型ジョブ**（実行中のジョブに JupyterLab / VS Code / SSH で入る） | **学習が進まない原因を、その場で調べられる**。RL は「回してみないと分からない」ので効果が非常に大きい | 03, 05 |
| **Sweep Job の平行座標プロット** | 「どのハイパラが成功率に効いたか」が視覚的に分かる | 08 |
| **`Choice` で乱数シードを探索空間にする** | **同一設定 × 複数シードの反復を Sweep 1本で回せる**（再現性評価） | 08 |
| **MLflow アーティファクト** | **評価動画（mp4）を Run に紐付けて保存できる** | 04, 05 |
| **コード スナップショット自動保存** | 「どの報酬関数のコードで出た結果か」が自動で残る | 05, 07 |
| **`rw_mount` 出力** | 学習途中のチェックポイントを逐次書き出せる | 05 |

## 0.6 使用する OSS とライセンス（要約）

| パッケージ | 提供元 | ライセンス | 役割 |
|---|---|---|---|
| **Gymnasium** | Farama Foundation | **MIT** | 強化学習環境の API 規約（`reset` / `step`） |
| **Stable-Baselines3** | DLR-RM | **MIT** | 強化学習アルゴリズムの実装（SAC / TD3 / PPO / HER） |
| **panda-gym** | Quentin Gallouédec | **MIT** | Panda ロボットのタスク環境（ピックアンドプレイス等） |
| **PyBullet / Bullet3** | Bullet Physics | **zlib** | 物理シミュレーション エンジン（panda-gym の依存） |

**すべて商用利用が可能な寛容型ライセンス**です。根拠 URL と注意点は [A2_OSSライセンス一覧.md](A2_OSSライセンス一覧.md) を参照してください。

> **なぜこの組み合わせを選んだか**
> ロボット強化学習の環境には MuJoCo ベース（Gymnasium-Robotics など）もあり、こちらも Apache-2.0 / MIT の寛容型ライセンスです。しかし **PyBullet ベースの panda-gym は `pip install` だけで完結し、ヘッドレス環境（Azure ML のコンピューティング）で動かしやすい**ため、**導入コストを下げる目的**で第一候補としています。
