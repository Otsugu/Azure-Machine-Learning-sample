## 5.1 【最初にやる】評価指標を決める

> ⚠ **実験を回す前に評価指標を決めてください。**
> 後から決めると、「良く見える指標」を後付けで選んでしまい、**評価が信用できなくなります。**

### 本ハンズオンの評価指標

| 区分 | 指標 | MLflow のメトリック名 | 意味 |
|---|---|---|---|
| **主指標** | **成功率** | `final_success_rate` | **タスクを達成できた割合。最重要** |
| 主指標 | 平均報酬 | `final_mean_reward` | 学習信号としての質 |
| **安定性** | 報酬の標準偏差 | `final_std_reward` | **ばらつき。平均だけで判断しないため** |
| 安定性 | 成功率の標準誤差 | `final_success_rate_stderr` | 成功率を「幅」で語るため |
| 効率 | 平均エピソード長 | `final_mean_episode_length` | 無駄な動きが多くないか |
| 計算資源 | 学習時間（分） | `train_minutes` | コストに直結 |
| 学習過程 | 評価成功率の推移 | `eval_success_rate`（step 付き） | **学習曲線** |
| 学習過程 | 評価報酬の推移 | `eval_mean_reward` / `eval_std_reward`（step 付き） | 報酬とそのばらつき |
| 学習過程 | 学習中の統計 | `rollout_ep_rew_mean` / `rollout_ep_len_mean` / `rollout_success_rate`（step 付き） | **探索ノイズを含む**学習中の挙動 |

> **重要（なぜ「成功率」と「平均報酬」を両方記録するのか）**
> **報酬が上がっても成功率が上がらないとき、それは報酬ハッキングのサインです**（[01 章](01_強化学習の基礎.md) 1.7）。
> この 2 つを突き合わせられるようにしておくことが、**評価の生命線**です。

### 【重要な設計判断】評価は常に「同じものさし」で行う

[src/train_rl.py](../src/train_rl.py) は、**学習時の報酬設計にかかわらず、評価は常に `sparse` 報酬で行います。**

```python
EVAL_REWARD_MODE = "sparse"   # ← 学習が dense でも shaped でも、評価は常に sparse
```

> **なぜか**
> 学習時の報酬設計をそのまま評価に使うと、**条件ごとに「ものさし」が変わってしまい、`mean_reward` を条件間で比較できません。**
> 例: dense 報酬は値域が違うので、sparse 条件の報酬と比べても意味がありません。
>
> 「**同一の評価指標で比較する**」という実験設計の原則を守るための措置です。
>
> なお **成功率は `info["is_success"]` 由来なので、報酬設計に依存せずもともと比較可能**です。

## 5.2 学習スクリプトの読み解き

[src/](../src/) には 3 つの Python ファイルがあります。**役割を理解してから実行してください。**

| ファイル | 役割 | 改善実験で変更するか |
|---|---|---|
| [src/rl_env_factory.py](../src/rl_env_factory.py) | **環境の生成と報酬ラッパー** | **演習1（報酬関数）で変更** |
| [src/train_rl.py](../src/train_rl.py) | 学習の本体・MLflow 記録 | **原則変更しない**（引数だけ変える） |
| [src/evaluate.py](../src/evaluate.py) | 評価と動画収録 | 原則変更しない |

> **重要な原則**: **「コードを書き換える」のではなく「引数を変える」**ようにしてください。
> こうすることで、**MLflow に記録されたパラメーターだけで実験を完全に再現できます。**

### 主要な引数

```bash
python train_rl.py \
  --env-id PandaPickAndPlace-v3 \
  --algo sac \
  --use-her 1 \
  --reward-mode sparse \
  --total-timesteps 50000 \
  --seed 0 \
  --learning-rate 0.0003 \
  --gamma 0.99 \
  --batch-size 256
```

| 引数 | 意味 | ベースライン値 |
|---|---|---|
| `--env-id` | 課題 | `PandaPickAndPlace-v3` |
| `--algo` | アルゴリズム | `sac` |
| `--use-her` | **HER を使うか**（1/0） | `1` |
| `--reward-mode` | 報酬設計 | `sparse` |
| `--total-timesteps` | 学習量 | `50000` |
| `--seed` | 乱数シード | `0` |
| `--learning-rate` | **学習率**（演習2 の主役） | `0.0003` |
| `--gamma` | **割引率**（演習2 の主役） | `0.99` |
| `--batch-size` | **バッチサイズ**（演習2 の主役） | `256` |
| `--buffer-size` | リプレイバッファサイズ | `200000` |
| `--learning-starts` | 学習を始めるまでの収集ステップ数 | `1000` |
| `--n-sampled-goal` | HER が 1 経験から作る仮想経験の数 | `4` |
| `--goal-selection-strategy` | HER のゴール選択方式 | `future` |
| `--eval-freq` | 何タイムステップごとに評価するか | `5000` |
| `--n-eval-episodes` | 学習中の評価エピソード数 | `30` |
| `--final-eval-episodes` | **最終評価**のエピソード数 | `100` |
| `--record-video` | 評価動画を収録するか（1/0） | `1` |
| `--reward-fn-version` | **報酬関数の版**。変更したら必ず上げる | `v1` |

> ⚠ **`--total-timesteps 50000` は「短時間で必ず終わる値」として設定しています。**
> **これは「学習を完成させるには足りない値」です。** 本ハンズオンの目的はモデルの完成ではなく、
> **実験を実行・記録・比較できるようになること**です（本ハンズオンの完了条件も同様です）。

### 【重要】描画設定 — 学習ジョブは常に `rgb_array` ＋ `Tiny`

学習ジョブは **Azure ML Compute（ヘッドレス）** で動きます。そのため描画の設定が固定されています。

| フェーズ | 描画 | 理由 |
|---|---|---|
| **学習中** | **描画しない**（`render=False`） | **物理演算より描画のほうが重い。** 描画すると学習が大幅に遅くなる |
| **評価・動画収録** | `render_mode="rgb_array"` ＋ `renderer="Tiny"` | **ヘッドレスで動く唯一の方法**。報酬ハッキング検出のため動画は必須 |

> ⚠ **`render_mode="human"` は Azure ML Compute では使えません。**
> GUI（OpenGL ウィンドウ）を開こうとするためです。**GUI はローカル実行専用**です（[04 章](04_RL環境を触って理解する.md) 4.6）。

#### なぜ `Tiny` なのか — PyBullet 公式の根拠

panda-gym の `renderer="Tiny"` は、内部で PyBullet の **`p.DIRECT`** 接続になります
（`renderer="OpenGL"` は `p.GUI`）。

> 出典（参考情報・OSS 公式ソース）: [panda_gym/pybullet.py](https://raw.githubusercontent.com/qgallouedec/panda-gym/master/panda_gym/pybullet.py)

そして PyBullet の公式ガイドは、`DIRECT` について次のように述べています。

> "The DIRECT connection sends the commands directly to the physics engine, without using any transport layer and **no graphics visualization window**"
>
> "Note that in **DIRECT mode you cannot access the OpenGL and VR hardware features** ... DIRECT mode does allow rendering of images using the built-in software renderer through the 'getCameraImage' API. **This can be useful for running simulations in the cloud on servers without GPU.**"
>
> → 出典（参考情報・OSS 公式ドキュメント）: [PyBullet Quickstart Guide](https://raw.githubusercontent.com/bulletphysics/bullet3/master/docs/pybullet_quickstart_guide/PyBulletQuickstartGuide.md.html)

> **つまり「GPU の無いクラウド サーバーでシミュレーションを回す」用途は、PyBullet が公式に想定している使い方です。**
> **本ハンズオンが CPU クラスターで完結できるのは、この仕組みのおかげです。**

> **補足**: `DIRECT` モードでは **`setRealTimeSimulation` が効きません**（物理サーバーが別スレッドで動かないため）。
> 学習では `step()` を明示的に呼ぶので問題ありません。（出典: 同上）

実装は [src/rl_env_factory.py](../src/rl_env_factory.py) の `make_env(..., render=...)` に集約されています。
**学習用の環境は `render=False`、評価・動画用の環境だけ `render=True`** で作られます。

---

### 【重要】HER と報酬ラッパーの整合性

[src/rl_env_factory.py](../src/rl_env_factory.py) には、**強化学習で最も発見しにくいバグ**への対策が入っています。

> **問題**: HER はリプレイ時に**ゴールを差し替えて報酬を再計算**します。その再計算には環境の `compute_reward()` を使います。
> もし `step()` の報酬だけをラッパーで書き換えると、
>
> | | 使われる報酬関数 |
> |---|---|
> | `step()` が返す報酬 | **変更後** |
> | HER が再計算する報酬 | **変更前** |
>
> となり、**エラーにならずに学習信号だけが静かに壊れます。**
>
> **対策**: `ShapedRewardWrapper` は `step()` と `compute_reward()` の**両方**を差し替え、
> さらに `verify_reward_consistency()` で**環境生成のたびに一致を実行時検証**します。
>
> 出典（参考情報・OSS 公式ドキュメント）: https://stable-baselines3.readthedocs.io/en/master/modules/her.html

## 5.3 MLflow ログ設計（何を残すか）

実験の「記録対象」を、実装に落とし込んだものが以下です。

### パラメーター（`mlflow.log_param`）— **後から変えられない実験条件**

| 分類 | 記録する項目 |
|---|---|
| 課題 | `env_id`, `actual_env_id`, `reward_mode`, `shaping_weight` |
| 環境の実態（`describe_env` 由来） | `env_env_id`, `env_max_episode_steps`, `env_observation_keys`, `env_action_dim`, `env_action_low`, `env_action_high` |
| アルゴリズム | `algo`, `use_her`, **`her_effective`**, `n_sampled_goal`, `goal_selection_strategy` |
| ハイパーパラメーター | `learning_rate`, `gamma`, `batch_size`, `buffer_size`, `learning_starts` |
| 実験条件 | `total_timesteps`, **`seed`**, `n_envs` |
| 評価条件 | `eval_freq`, `n_eval_episodes`, `final_eval_episodes`, **`eval_reward_mode`**, `record_video`, `video_episodes` |
| **環境のバージョン** | `python_version`, `numpy_version`, `gymnasium_version`, `panda_gym_version`, `sb3_version`, `torch_version` |
| 版管理 | `reward_fn_version`, `output_dir` |

> **補足**: [src/train_rl.py](../src/train_rl.py) は **すべてのコマンドライン引数をそのまま `log_param` します**（`for key, value in sorted(vars(args).items())`）。
> つまり **引数を追加すれば自動で記録されます。** 上表はそのうち重要なものを分類したものです。
> `her_effective` だけは引数ではなく、**実際に HER が有効になったか**を示す値です（PPO では 0 になります）。

> **重要**: **ライブラリのバージョンを必ず記録してください。**
> 強化学習は乱数と数値計算に敏感なため、**「同じコード・同じ引数でも、ライブラリの版が違えば結果が変わる」**ことが普通にあります。

### メトリック（`mlflow.log_metric`）— **時系列で変化する値**

**すべてのメトリックは、接頭辞で 3 つに分けています。**

| 接頭辞 | いつの値か | ステップ付き |
|---|---|---|
| **`rollout_`** | **学習中**の統計（Monitor が集めたもの。探索ノイズを含む） | あり |
| **`eval_`** | **学習途中の評価**（決定的行動。学習曲線になる） | あり |
| **`final_`** | **最終評価**（エピソード数を増やして精度を上げたもの） | なし |

| 名前 | 意味 |
|---|---|
| `rollout_ep_rew_mean` / `rollout_ep_len_mean` / `rollout_success_rate` | **学習中**の報酬・エピソード長・成功率 |
| `eval_success_rate` | 評価時の成功率（**学習曲線の主役**） |
| `eval_mean_reward` / `eval_std_reward` | 評価時の報酬とそのばらつき |
| `eval_min_reward` / `eval_max_reward` | 最悪ケースと最良ケース |
| `eval_mean_episode_length` / `eval_std_episode_length` | エピソード長 |
| `eval_success_rate_stderr` | 成功率の標準誤差 |
| `eval_best_success_rate` | それまでの最良値（単調増加） |
| `final_*` | 上記と同じ項目の**最終評価版** |
| `train_seconds` / `train_minutes` | 学習時間 |
| `video_recorded` | 動画収録に成功したか（1/0） |

> **重要**: **`rollout_success_rate` と `eval_success_rate` は一致しません。**
> 前者は**探索ノイズを含む学習中の行動**、後者は**決定的行動**での評価です。
> 報告に使うのは **`final_success_rate`** です。

> **重要**: メトリック名に **`/` を使わず平坦にしています。**
> **Sweep Job の `primary_metric` にそのまま指定できるようにするため**です（[08 章](08_演習2_ハイパーパラメータ改善.md)）。

### 成果物（`mlflow.log_artifact`）

| ファイル | 用途 |
|---|---|
| **`eval_video.mp4`** | **報酬ハッキングの検出（最重要）** |
| `model.zip` | 学習済み方策 |
| `pip_freeze.txt` | **実際に解決されたパッケージ版の証跡** |
| `run_summary.json` | 条件と結果のまとめ（比較表の作成に使う） |

> ⚠ **HER を使ったモデルの読み込みには環境が必須です。**
> ```python
> model = SAC.load("model.zip", env=env)   # env を必ず渡す
> ```

### 「失敗の分類」を記録する（[01 章](01_強化学習の基礎.md) 1.3 の続き）

エピソード長と `is_success` の組み合わせで、失敗の種類をおおまかに切り分けられます。

| `is_success` | エピソード長 | 解釈 |
|---|---|---|
| True | 短い | **良い成功**（素早く達成） |
| True | 長い | 成功はしたが非効率 |
| False | **50（上限）** | **時間切れ**（そもそも到達していない） |
| False | 短い | 到達したが外れた／不安定 |

`final_mean_episode_length` と `final_success_rate` を突き合わせて判断してください。

## 5.8 【推奨】学習が進まないときの対話型デバッグ

**強化学習は「回してみないと分からない」ため、ログだけで原因を追うと時間を浪費します。**
Azure ML の**対話型ジョブ**を使うと、実行中のジョブの中に入って調べられます（[03 章](03_AzureML環境構築.md) 3.8）。

```python
from azure.ai.ml.entities import JupyterLabJobService, VsCodeJobService

job = command(
    code="../src",
    command="python train_rl.py --total-timesteps 5000 ; sleep 30m",   # ← 調査時間を確保
    environment=ENV_REF,
    compute=COMPUTE_NAME,
    services={"jlab": JupyterLabJobService(), "vscode": VsCodeJobService()},
)
```

入ってから確認すべきこと:

1. `env.observation_space` は辞書型か
2. `env.step()` の報酬は想定どおりか
3. `info["is_success"]` は返ってきているか
4. HER が有効になっているか（`model.replay_buffer.__class__.__name__`）

> ⚠ **`sleep infinity` は使わないでください。** 手動キャンセルしない限り課金が続きます（[03 章](03_AzureML環境構築.md) 3.8）。

## 5.9 チェックポイントと中断への備え

長時間の学習では、**中断されても再開できるようにしておく**のが定石です。
Azure ML では、ジョブ出力のモードに **`rw_mount`** を使うと、**マウントされたディレクトリに逐次書き出せます。**

> **出典: Microsoft Learn** — [Access data in a job（モード）](https://learn.microsoft.com/azure/machine-learning/how-to-read-write-data-v2?view=azureml-api-2#modes)
> `rw_mount` は読み書き可能なマウント、`upload` はジョブ終了時にまとめてアップロードします。

本ハンズオンの学習時間では必須ではありませんが、
**Spot（低優先度）の計算資源を使う場合は必須の設計**になります（[09 章](09_評価・コスト・後片付け.md)）。

## ⚠ うまくいかないときは（Step 05）

| # | 症状 | 主な原因 | 確認手順 | 対処 |
|---|---|---|---|---|
| 1 | ジョブが `Failed`。原因が分からない | — | **［出力とログ］→ `user_logs/std_log.txt`** | トレースバックの**最終行**から読む。環境構築の失敗なら `system_logs/` |
| 2 | `ModuleNotFoundError: No module named 'evaluate'` | `code=` の指定が誤り／ファイルが同梱されていない | studio ［コード］タブでスナップショットの中身を確認 | `code="../src"` を指定し、`train_rl.py` と同じ階層に `evaluate.py` があることを確認 |
| 3 | `RuntimeError: panda-gym は numpy<2 を要求します` | numpy 2.x が入った | ログの `numpy_version` | `conda.yaml` の `"numpy<2"` を確認して環境を作り直す |
| 4 | `RuntimeError: step() の報酬と compute_reward() の戻り値が一致しません` | **報酬ラッパーの実装ミス** | エラーメッセージ内の 2 つの値 | `ShapedRewardWrapper.compute_reward` を修正する。**この検証は HER の破損を防ぐためのもの** |
| 5 | `KeyError: 'is_success'` | Monitor の `info_keywords` が拾えていない | 環境が `info["is_success"]` を返すか | panda-gym 以外の環境に差し替えた場合は `info_keywords` を外す |
| 6 | 学習が進まない（成功率が 0 のまま） | **PickAndPlace ＋ 疎な報酬では正常**（[01 章](01_強化学習の基礎.md) 1.4） | `eval_success_rate` の推移 | **これがベースラインの結果です。** HER あり／なしを比較して [06 章](06_結果の読み解き.md) へ |
| 7 | 学習が極端に遅い | `n_envs=1` で CPU を使い切れていない | studio ［監視］の CPU 使用率 | `--n-envs 4` を試す。ただし**結果の比較可能性のためベースラインは変えない** |
| 8 | メトリックが 1 点しか出ない | `--eval-freq` が `--total-timesteps` より大きい | 引数の値 | `--eval-freq` を小さくする（例: `2000`） |
| 9 | `video_recorded` が 0 | `render()` が None／`imageio-ffmpeg` が無い | `std_log.txt` の `[WARN]` 行 | [04 章](04_RL環境を触って理解する.md) の TS #5, #8 を参照 |
| 10 | ジョブが `Queued` のまま | クォータ不足／`max_instances` 到達 | studio ［クォータ］、クラスターのノード数 | [02 章](02_Azure環境の準備.md) 2.3。並列投入数を減らす |
| 11 | 3 本同時に投げたら 1 本だけ進まない | `max_instances` が足りない | クラスターの設定 | `max_instances` を増やす（クォータの範囲内で） |
| 12 | 学習済みモデルを読み込めない（HER 使用時） | **`env` を渡していない** | `SAC.load(...)` の呼び出し | `SAC.load(path, env=env)` とする（[01 章](01_強化学習の基礎.md) 1.5） |
| 13 | 同じ引数で 2 回回したのに結果が違う | **乱数シードの影響（正常）** | `seed` パラメーター | [01 章](01_強化学習の基礎.md) 1.8。**複数シードで反復する**（[08 章](08_演習2_ハイパーパラメータ改善.md)） |
