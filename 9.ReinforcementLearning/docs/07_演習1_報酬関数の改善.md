## 7.1 報酬設計の原則と副作用

### 原則

| 原則 | 理由 |
|---|---|
| **成功の定義から出発する** | 報酬は「成功に近づく度合い」を表すもの。定義が曖昧なら報酬も曖昧になる |
| **一度に 1 つだけ変える** | 効果を切り分けられなくなる |
| **重み（スケール）を意識する** | 追加項が大きすぎると**元の目的を上書きしてしまう** |
| **副作用を先に想像する** | 「この報酬を最大化する最短の抜け道は何か？」と自問する |

> ⚠ **最重要**: **報酬を足すたびに「抜け道」も増えます。**
> 実験を投入する**前に**、「エージェントがこの報酬をズルして稼ぐ方法は何か」を書き出してください。

### 本ハンズオンで比較する 4 条件

[src/rl_env_factory.py](../src/rl_env_factory.py) の `REWARD_MODES` に実装されています。

| `--reward-mode` | 報酬 | 想定される効果 | **想定される副作用** |
|---|---|---|---|
| **`sparse`**（ベースライン） | 成功 0 / 失敗 -1 | 抜け道が少ない | **学習がほぼ進まない** |
| **`dense`** | -（キューブと目標の距離） | 学習が速くなる | **押すだけで距離が縮むので、押す行動が強化されやすい** |
| **`sparse_shaped`** | sparse - w×距離 | 疎な報酬に手がかりを足す | w が大きいと dense と同じ副作用。**w が小さいと効果が出ない** |
| **`sparse_time_penalty`** | sparse - w（毎ステップ） | 素早い達成を促す | **「早く失敗して終わらせる」方向に働く危険** |

> **`dense` の実体**（検証済み）
> panda-gym の Dense 版環境は `compute_reward` が **`-d`（目標との距離のマイナス）** を返します。
> 出典（参考情報・OSS 公式ソース）: [panda_gym/envs/tasks/pick_and_place.py](https://github.com/qgallouedec/panda-gym/blob/master/panda_gym/envs/tasks/pick_and_place.py)

## 7.2 実装のしくみ（報酬をどう差し替えているか）

### 2 つの方式を使い分けています

| 方式 | 使う条件 | どうやるか |
|---|---|---|
| **環境 ID を差し替える** | `dense` | panda-gym の Dense 版環境（`PandaPickAndPlaceDense-v3`）を使う |
| **ラッパーで報酬を書き換える** | `sparse_shaped` / `sparse_time_penalty` | `ShapedRewardWrapper` を被せる |

### 【最重要】HER と整合させるための実装

> ⚠ **強化学習で最も発見しにくいバグがここにあります。**
>
> HER はリプレイのたびに**ゴールを差し替えて報酬を再計算**します。その再計算には環境の **`compute_reward()`** を使います。
> もし `step()` の報酬だけをラッパーで書き換えると：
>
> | | 使われる報酬関数 |
> |---|---|
> | `step()` が返す報酬 | **変更後** |
> | HER が再計算する報酬 | **変更前** |
>
> となり、**エラーにならずに学習信号だけが静かに壊れます。**

**対策**（[src/rl_env_factory.py](../src/rl_env_factory.py)）:

1. `ShapedRewardWrapper` は **`step()` と `compute_reward()` の両方**を同じ式で差し替える
2. `compute_reward()` は **ベクトル化**（配列をまとめて処理）されている — HER の要件
3. **`verify_reward_consistency()` が環境生成のたびに一致を実行時検証する**

```python
# 一致しなければ RuntimeError で即座に止まる
RuntimeError: step() の報酬と compute_reward() の戻り値が一致しません。
```

> **重要**: **自分で報酬関数を追加するときは、必ず `compute_reward()` 側も直してください。**
> 直し忘れても `verify_reward_consistency()` が捕まえます。

> 出典（参考情報・OSS 公式ドキュメント）: https://stable-baselines3.readthedocs.io/en/master/modules/her.html

## 7.4 実験を実行する

変更するのは **`--reward-mode` と `--shaping-weight` だけ**です。
他の引数はベースラインと同一にします（**一度に 1 要素だけ変える**原則）。

```bash
python train_rl.py --env-id PandaPickAndPlace-v3 --use-her 1 \
  --reward-mode dense \
  --total-timesteps 50000 --seed 0 --learning-rate 0.0003 --gamma 0.99 --batch-size 256
```

### 【重要】評価は常に同じものさしで行われます

[src/train_rl.py](../src/train_rl.py) は、**学習時の報酬設計にかかわらず、評価は常に `sparse` で行います。**

> **なぜか**: dense 報酬と sparse 報酬では**値域が違う**ため、`mean_reward` をそのまま比べても意味がありません。

## 7.8 環境そのもののパラメータを変える

> [!TIP]
> **深く理解するために**
>
> 本節は必須ではありません。**7.7 で「議論に留める」とした環境側の改変を、実際にやるならどうするか**を示します。
> 「報酬関数とハイパーパラメーターしか変えられない」と思い込むと、**課題設定そのものが原因のとき**に手詰まりになります。

### 7.8.1 まず「どこまで `gym.make` から変えられるか」を知る

`PandaPickAndPlace-v3` の実体 `PandaPickAndPlaceEnv` が受け取る引数は、**次で全部**です（**ソースで確認済み**）。

| `gym.make` に渡せる引数 | 既定値 | 意味 |
|---|---|---|
| `render_mode` | `"rgb_array"` | 描画モード（[04 章](04_RL環境を触って理解する.md) 4.6） |
| `reward_type` | `"sparse"` | `"sparse"` / `"dense"`。**本テキストは `-v3` / `Dense-v3` の ID 差し替えで扱っています**（7.2） |
| `control_type` | `"ee"` | `"ee"` は手先位置制御（行動 4 次元）、`"joints"` は関節制御（行動 8 次元） |
| `renderer` | `"Tiny"` | `"Tiny"`（DIRECT）／`"OpenGL"`（GUI） |
| `render_width` / `render_height` | `720` / `480` | 動画の解像度 |
| `render_target_position` / `render_distance` / `render_yaw` / `render_pitch` / `render_roll` | `[0,0,0]` / `1.4` / `45` / `-30` / `0` | カメラ（[04 章](04_RL環境を触って理解する.md) 4.6.3） |

> **出典（参考情報・OSS 公式ソース）**: [panda_gym/envs/panda_tasks.py](https://github.com/qgallouedec/panda-gym/blob/master/panda_gym/envs/panda_tasks.py)

> [!WARNING]
> **`distance_threshold`（成功しきい値）、`goal_xy_range` / `goal_z_range`（目標のばらつき）、`obj_xy_range`（物体のばらつき）は `gym.make` から渡せません。**
> `PandaPickAndPlaceEnv.__init__` が `PickAndPlace(sim, reward_type=reward_type)` としか呼んでいないためです（ソース確認済み）。
> 変えたい場合は 7.8.3 の方法を使ってください。

### 7.8.2 エピソード長（`max_episode_steps`）を変える

これは **Gymnasium の標準機能**で変更できます。

> **出典（参考情報・OSS 公式ドキュメント）**: [gymnasium.make - Gymnasium Documentation](https://gymnasium.farama.org/api/registry/)
> 「`max_episode_steps` — Maximum length of an episode, **can override the registered `EnvSpec` `max_episode_steps`** with the value being passed to `gymnasium.wrappers.TimeLimit`. Using `max_episode_steps=-1` will not apply the wrapper to the environment.」

```python
# 既定の 50 ステップを 100 ステップに延ばす
env = gym.make("PandaPickAndPlace-v3", max_episode_steps=100)
```

| 変えるとどうなるか | 根拠 |
|---|---|
| **1 エピソードで使える手数が増える**（手先の移動は 1 ステップ最大 5 cm） | [04 章](04_RL環境を触って理解する.md) 4.6.4 |
| **`truncated` の発生タイミングが変わる** | `RobotTaskEnv.step()` 自体は常に `truncated=False` を返し、打ち切りは `TimeLimit` ラッパーが行う（ソース確認済み） |
| **`final_mean_episode_length` の解釈が変わる** | 「上限に張り付き＝時間切れ」の判定基準が 50 でなくなる（[05 章](05_ベースライン実験.md) 5.3、[06 章](06_結果の読み解き.md) 6.0.1） |
| **1 エピソードの計算時間が増える** → 同じ `--total-timesteps` でもエピソード数は減る | — |

### 7.8.3 成功しきい値（`distance_threshold`）を変える

`gym.make` からは渡せませんが、**生成後にタスク オブジェクトの属性を書き換えれば変更できます。**
`is_success()` と `compute_reward()` の**両方が実行時に `self.distance_threshold` を読む**ためです（ソース確認済み）。

```python
env = gym.make("PandaPickAndPlace-v3")
env.unwrapped.task.distance_threshold = 0.03   # 既定 0.05 → 3 cm に厳しくする
```

> **出典（参考情報・OSS 公式ソース）**: [panda_gym/envs/tasks/pick_and_place.py](https://github.com/qgallouedec/panda-gym/blob/master/panda_gym/envs/tasks/pick_and_place.py)
> ```python
> def is_success(self, achieved_goal, desired_goal, info={}):
>     d = distance(achieved_goal, desired_goal)
>     return np.array(d < self.distance_threshold, dtype=bool)
>
> def compute_reward(self, achieved_goal, desired_goal, info={}):
>     d = distance(achieved_goal, desired_goal)
>     if self.reward_type == "sparse":
>         return -np.array(d > self.distance_threshold, dtype=np.float32)
>     else:
>         return -d.astype(np.float32)
> ```

> [!WARNING]
> **`distance_threshold` を変えると、成功判定と報酬の両方が同時に変わります。**
>
> - `is_success` が厳しくなる ＝ **`terminated` の条件も厳しくなる**（`RobotTaskEnv.step()` は `terminated = is_success(...)`）
> - `sparse` 報酬の定義も変わる ＝ **HER が再計算する報酬も変わる**
> - つまり **「成功率」という指標の意味自体が変わります。** しきい値の違う実験同士の `final_success_rate` を並べて比較してはいけません

### 7.8.4 目標・物体のばらつきを変える（環境を直接組み立てる）

`goal_xy_range` / `goal_z_range` / `obj_xy_range` は `PickAndPlace` のコンストラクタ引数ですが、`gym.make` からは届きません。変えるなら **`RobotTaskEnv` を自分で組み立てます。**

```python
import numpy as np
from panda_gym.envs.core import RobotTaskEnv
from panda_gym.envs.robots.panda import Panda
from panda_gym.envs.tasks.pick_and_place import PickAndPlace
from panda_gym.pybullet import PyBullet

sim = PyBullet(render_mode="rgb_array", renderer="Tiny")
robot = Panda(sim, block_gripper=False, base_position=np.array([-0.6, 0.0, 0.0]), control_type="ee")
task = PickAndPlace(sim, reward_type="sparse", goal_z_range=0.0)   # 目標を常にテーブル上にする
env = RobotTaskEnv(robot, task)
```

> **出典（参考情報・OSS 公式ソース）**: [panda_gym/envs/panda_tasks.py](https://github.com/qgallouedec/panda-gym/blob/master/panda_gym/envs/panda_tasks.py)（上のコードは `PandaPickAndPlaceEnv.__init__` の構築手順をそのままなぞったものです）

> [!NOTE]
> **`goal_z_range=0.0` にすると目標は常にテーブル上（z ≒ キューブ半分の高さ）になります。**
> `_sample_goal()` は `noise = uniform(goal_range_low, goal_range_high)` を加算し、さらに **約 30% の確率で `noise[2] = 0.0`** にします（[04 章](04_RL環境を触って理解する.md) 4.5）。`goal_z_range=0.0` なら `noise[2]` は常に 0 です。
> **これは「持ち上げ不要のタスク」＝ 実質 Push に近い課題に変わります。** 難易度を下げた対照実験として有効ですが、**元の課題とは別のタスク**です。

> [!CAUTION]
> **この方法で作った環境には `TimeLimit` ラッパーが付きません。つまりエピソードが永遠に終わらなくなります。**
> `max_episode_steps` は **`gym.make` が登録情報（`EnvSpec`）から `TimeLimit` を適用することで効いています**（→ 7.8.2 の出典）。
> `RobotTaskEnv` を直接作るとこのラッパーが付かず、**`RobotTaskEnv.step()` は常に `truncated=False` を返す**ため、成功するまでエピソードが続きます（ソース確認済み）。
>
> **必ず自分でラッパーを付けてください。**
>
> ```python
> from gymnasium.wrappers import TimeLimit
> env = TimeLimit(RobotTaskEnv(robot, task), max_episode_steps=50)
> ```
>
> さらに、この環境は `gym.make` 経由ではないため **`env.spec` がなく、MLflow に記録される `env_env_id` 等の値が実態とずれます**（[src/rl_env_factory.py](../src/rl_env_factory.py) の `describe_env`）。変更内容は 7.8.5 のとおり手動で記録してください。

### 7.8.5 【最重要】変えたら必ず記録し、比較の範囲を限定する

> [!CAUTION]
> **環境パラメータの変更は、報酬関数やハイパーパラメーターの変更とは意味が違います。**
> 報酬やハイパラは「同じ課題の解き方」を変えるだけですが、**環境パラメータは「課題そのもの」を変えます。**
>
> **ベースライン（[05 章](05_ベースライン実験.md) 5.7）と横並びで比較してはいけません。**

変更した場合は、必ず次を記録してください。

| 記録する項目 | 方法 |
|---|---|
| 変更した環境パラメータと値 | `mlflow.log_param("env_max_episode_steps", ...)` など。[src/train_rl.py](../src/train_rl.py) は `describe_env` の結果を `env_*` として記録します（[05 章](05_ベースライン実験.md) 5.3） |
| **変更した理由と期待する結果** | 実行前にワークシート ⑤ へ（7.3 と同じ作法） |
| **比較してよい Run の範囲** | 「同じ環境設定同士でのみ比較する」と明記する |
| 実験名を分ける | 例: `rl-env-exp`（[05 章](05_ベースライン実験.md) 5.4 の命名規則に追加する） |

## ⚠ うまくいかないときは（Step 07）

| # | 症状 | 主な原因 | 確認手順 | 対処 |
|---|---|---|---|---|
| 1 | `RuntimeError: step() の報酬と compute_reward() の戻り値が一致しません` | **報酬ラッパーの実装ミス** | エラー内の 2 つの値 | `ShapedRewardWrapper.compute_reward()` を修正。**`step()` だけ直して満足しないこと** |
| 2 | `ValueError: 未知の reward_mode です` | 綴り間違い | `--reward-mode` の値 | `sparse` / `dense` / `sparse_shaped` / `sparse_time_penalty` のいずれか |
| 3 | `dense` にしたのに環境 ID が変わっていない | `resolve_env_id` の対象外 ID | MLflow の `actual_env_id` | 環境 ID が `-v3` で終わっているか確認 |
| 4 | 報酬が発散する（`nan` になる） | **シェーピングの重みが大きすぎる** | `--shaping-weight` の値 | 重みを 1/10 にして再実行。学習率も下げる |
| 5 | 4 条件の `mean_reward` が比較できない | 評価のものさしが違うと思っている | MLflow の `eval_reward_mode` | **すべて `sparse` になっているはず**（7.4 参照）。なっていなければ実装を確認 |
| 6 | 差が出たのか判断できない | **誤差を見ていない** | `final_success_rate_stderr` | [06 章](06_結果の読み解き.md) 6.4。誤差より小さい差は「差なし」 |
| 7 | 4 本同時に投げたら詰まる | `max_instances` / クォータ不足 | studio ［コンピューティング］ | 2 本ずつに分ける。[02 章](02_Azure環境の準備.md) 2.3 |
| 8 | どの Run がどの条件か分からない | 表示名・タグの不備 | studio ［ジョブ］ | 表示名に条件を入れる（[05 章](05_ベースライン実験.md) 5.4） |
| 9 | 動画を見ても違いが分からない | エピソード数が少ない | `--video-episodes` | `--video-episodes 5` などに増やす |
| 10 | **`gym.make(..., distance_threshold=0.03)` で `TypeError`** | **`distance_threshold` は `gym.make` の引数ではない**（仕様） | `panda_gym/envs/panda_tasks.py` | `env.unwrapped.task.distance_threshold = 0.03` とする（7.8.3） |
| 11 | `RobotTaskEnv` を直接作ったら**エピソードが終わらない** | **`TimeLimit` ラッパーが付いていない** | 環境の生成方法 | `TimeLimit(env, max_episode_steps=50)` で包む（7.8.4） |
| 12 | シリ間で `final_success_rate` の大小が逆転する | **`distance_threshold` を変えた実験を混ぜている** | MLflow の環境パラメーター | **しきい値が違う Run を並べて比較しない**。7.8.5 のとおり実験名を分ける |
